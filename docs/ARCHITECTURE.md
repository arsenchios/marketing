# Архитектура ArsLive

## Код и интерфейсы

React/TypeScript + Vite. Основные страницы: Dashboard (вебинары, записи, редактор), Studio (главный ведущий / спикер / ассистент / поддержка с разными разрешениями), Viewer (вход, ожидание, эфир, завершение), Statistics и Admin. `shared/contracts.ts` задаёт проверяемые схемы входных данных, `shared/brand.ts` — платформенный бренд. Основная геометрия в styles/theme; `arslive.css` накладывает светлую тему и анимацию без изменения медиапикселей.

## Данные и доступ

Express + WebSocket. SQLite для локальной разработки, PostgreSQL в public mode. Отдельная схема `arslive`, собственные cookie `al_*`, локальные ключи хранилища с префиксом ArsLive. Сервер проверяет компанию, событие, роль и срок доступа при HTTP и WebSocket запросах. Google OAuth с PKCE и состоянием, шифрование refresh tokens. Приглашения спикера и ассистента отзывные. Администратор помогает управлять, но не становится вторым отправителем основного потока.

Одна PostgreSQL advisory lock и медиасостояние процесса допускают один media worker. Вебинары можно создавать заранее, но проводить одновременно в этой версии — один.

## Видео и звук

Главный браузер собирает презентацию, аннотации и камеры на canvas; AudioContext смешивает звук. Спикер передаёт камеру/микрофон через WebRTC, по необходимости TURN. Обратный звук исключает собственный микрофон спикера (mix-minus). Спикер отображает презентацию и камеры локально; готовый canvas не отправляется ему отдельным тяжёлым потоком.

MediaRecorder ведущего отправляет фрагменты WebSocket на сервер. FFmpeg делает HLS для собственного сервера, MP4 для записи и RTMPS для YouTube, когда он включён и подключён. Начало речи отделено от подготовки доставки: перед стартом передаётся заставка, затем подтверждается готовность нужного выхода. Это не гарантирует нулевую задержку плеера зрителя.

При ухудшении отправки качество адаптируется, буферы ограничены, транспорт умеет переподключаться. Heartbeat очищает потерянные сокеты; ожидание первого подтверждения медиасокета ограничено. Начало, завершение, возврат в ожидание и повторный запуск сохраняют ссылку комнаты. Нажатие завершения сразу блокирует передачу новых кадров/голоса; зрители могут досмотреть уже принятый хвост. Браузерные правила autoplay, background playback и PiP зависят от устройства и источника видео.

## Презентации и архив

PDF, Office/OpenDocument и изображения нормализуются в слайды с лимитами количества, размера и времени. Office конвертируется отдельным процессом с ресурсными и сетевыми ограничениями. В production Docker проверяет конвертер на синтетическом PPTX. Изображения/документы проходят проверку типов; браузерные PDF задачи корректно освобождают память.

MP4 сначала появляется на постоянном volume. При настройке приватного R2 архивная очередь проверяет загруженный объект. Срок хранения файлов — 7 дней, удаления выполняются приложением, а не самим GitHub. Не считать локальную копию гарантированной без постоянного volume. YouTube сохраняет свою запись; её готовность и доступность не равны состоянию R2. Метаданные, пользователи, чат и статистика хранятся в БД.

## Границы текущей версии

- Несколько одновременных эфиров и горизонтальное масштабирование требуют отдельных медиаворкеров, распределённого владения и маршрутизации.
- После аварийного завершения процесса закрытие оставшегося live YouTube broadcast может требовать ручного действия. Постоянная очередь сверки/завершения YouTube — следующий этап, не обещанная реализованная функция.
- Локальные loopback тесты не подтверждают реальные Safari/iPhone, межсетевой TURN, права канала, задержку провайдера или качество микрофона.
- Для нового публичного сервиса нужны собственные юридические тексты о данных, резервное копирование, мониторинг и приёмка инфраструктуры. Код не подключает их автоматически.
